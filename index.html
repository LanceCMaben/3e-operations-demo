How to Use 3E Operations

Internal Operations Overview card with chapter-style navigation. Start on Operations to pick a chapter, or use the chapter bar at the top. Use Light, System, or Dark in the header. Chapter URLs use a hash (for example #campaignTimelines or #partnerDataHealth).

Chapters

  • Overview — set Partner, Campaign, Year, and Program Status, then open a chapter. The same filter bar is on Partner Data Health and Campaign Upload QA.
  • Partner Data Health — program activity, partner files, downloads, daily load, and campaign totals (rebuild of Analyzer page 559098403).
  • Print Batches — on-demand and batch print status from PRINT_BATCHES.
  • Campaign Upload QA — partition upload freshness from Enrollment Metrics (XPL fallback). Uses the same Partner / Campaign / Year / Program Status filters as Partner Data Health. Verbose campaign names map onto codes (CNVA, CNVAU, AWR, and the rest) before joining program activity. Late statuses only include Active programs for that partner + campaign + year. Click a roster row for a client detail panel (upload freshness, matched program, and other campaigns for that client). Year pills: CY25 and CY26. Campaign tabs: All, CNVA, CNVAU, CNVAA, CNVAAFF, CNVASC, CNVD, AWR. Export stale partitions (>10 days) to Excel.
  • Campaign Timelines — Programs Timeline gantt from TOP_PROGRAMS_ACTIVITY_STATUS (Analyzer page 1151828266). Row is client (PARTITION); bar is first → last activity; color is campaign year. Gold marker = campaign dashboard availability (first activity + 14 days).
  • Campaign Load History — cumulative membership chart and daily load from leads_programs_xpl keyed on MEMBERSHIP_DATE. Opens on HighPoint (CNVA when that campaign exists) and loads it, unless Overview scope already has a partner. PIT student table is unfiltered.
  • Program Meta — one card per campaign from VW_PROGRAM_META, joined to email skew, last partner download date, and program activity. Status is the PROGRAM_STATUS value from TOP_PROGRAMS_ACTIVITY_STATUS, matched on PROGRAM_ID. Cards also show whether Returns, MAP, and Dashboards are on (Dashboards is first activity + 14 days), last download, market revision/tier, print ready, and email skew when a match exists. CY26 cards also show Data Quality: a green, yellow, or red status pill (blank is red Pending) and notes when DQ_NOTES has text.
  • Insights Activity — portal page views (legacy Analyzer page 2074513896): Portal, date range, partition, and dashboard filters (Apply / Reset), KPI strip, sortable tables, drill-down detail, est. dwell, and Export CSV on Recent Activity. Overview scope chips are informational on this chapter — they do not filter the activity log. Deep link: #insightsActivity (legacy #insightsUsage still works).
  • Documentation — opens on Portal & Launch. Dashboard Process Overview is a vertical build path; hover a step or a chapter box, and click a step for the checklist. Other tabs cover tools, Dev vs Prod, and guardrails. Deep link: #howWeBuild.

Filters

  • Overview, Partner Data Health, and Campaign Upload QA share the filter bar under the chapter tabs. Change Partner, Campaign, Year, or Status, then click Apply. Use the search box inside each dropdown to narrow its checklist. Reset clears Overview scope (partner, campaign, year, and inherited portal partition) and sets Program Status to All statuses — pick scope again and Apply to reload tables. Partner Data Health shows Activity, Files, Downloads, Daily Load, and Totals on one page. Deep links can scroll to a table, for example #partnerDataHealth/downloads.
  • Other chapters keep their own controls (year pills, program tabs, client pickers). Choose Partner (and optionally Campaign / Year) under Partner Data Health or Campaign Upload QA, then click Apply — that Overview scope flows to Program Meta, Timelines, Load History, and Print Batches (chips on those chapters summarize what is inherited). Insights Activity uses its own filters only; Overview scope is shown for context. Portal PARTITION filters apply the same way when the scope filter bar is set to all partners. Program Meta still has Returns, MAP, Dashboards, Last download, and Status filters local to that chapter. Status lists the raw PROGRAM_STATUS values from program activity (matched on program ID) and does not follow the Overview Active / Inactive / Development filter. Chapter Reset returns Program Meta to the latest year and all statuses, then puts the current Overview partner, campaign, and year back when that scope is set.
  • Partner, Campaign, and Campaign Year are multi-select. Leave empty for all. Opening any one of those three opens all three together; options update live as you check partners (for example pick High Point and the campaign and year lists immediately show only what applies). Options also cascade in every direction. Each dropdown has Clear section; Reset clears everything at once.
  • Program Status filters Program Activity, partner files, downloads, daily load, and campaign totals: Active, Inactive, and Development (from PROGRAM_STATUS / ACTIVE_FLAG). A row with no matched program stays visible. Default is All statuses.
  • Portal page filters should use PARTITION, not CLIENT. The latest campaign year is selected on first load so heavy tables stay small.
  • Partners whose partition name starts with z_ are excluded from filters, tables, and rosters (test/sandbox accounts).

Dashboard availability

  • Campaign dashboards — expected in the client portal about two weeks after the program’s first activity (FIRST_ACTIVITY from TOP_PROGRAMS_ACTIVITY_STATUS). Partner Data Health and Campaign Upload QA show this date on program detail; Campaign Timelines marks it on the gantt.
  • Cross-campaign dashboards — timing follows the CNVA program for the same partner and campaign year (year switch and launch). When CNVA exists, Partner Data Health shows a separate Cross-campaign availability line on the detail drawer. Finer rules for specific portal pages may still need ops confirmation.

Tables

  • Program Activity — first/last activity and days since last touched from TOP_PROGRAMS_ACTIVITY_STATUS. Click a row on any Partner Data Health table to open a detail panel with file funnel, downloads, daily load, and campaign totals. Use Export program report or Export latest file report in the drawer, or Export table on a card to download the filtered rows as Excel. Campaign Upload QA roster rows open a client detail panel; use Open in Partner Data Health when a program match exists.
  • Partner Data Files Detail — funnel counts from PARTNER_FILES_SUMMARY using the Analyzer column names: APP_ST (App Started), APP_SUB (App Submits), APP_COMP (Apps Complete), APP_STXSUB (started not submitted; a negative source count is shown as 0, and the detail drawer states the source value), plus admits/deposits/enrollments and the rest of the file metrics. Partner and campaign stay pinned while you scroll sideways. Rows are clickable; Export table downloads the current filter set.
  • Partner Downloads — download events from VW_PARTNER_DOWNLOADS_KMK, matching Analyzer card PDH Partner Downloads: Download Date (EVENT_DATE), Partner (CLIENT), Campaign (CAMPAIGN), Campaign Year (CY or CAMPAIGN_YEAR; a CY## token in the file name is used only when those columns return nothing), and File (FILE_NAME). Overview scope year and campaign filters match tokens/codes (so 2026 lines up with CY26, and CNVA lines up with Conversion Apply). Program Status applies the same way as the file and load tables. Undated return files such as DAO drop out when a year is selected. Click a row for program details; Export table downloads the current view.
  • Daily Load Details — membership load by date from PROGRAM_LOAD_HISTORY, with a running total of records loaded. Click a row for program details; Export table includes the running total.
  • Campaign Totals — record counts from PARTNER DASH LEADS_PROGRAMS_XPL, aggregated for the selected year and/or partner. Click a row for program details; Export table downloads the current view.
  • Each table shows 50 rows per page. Files apply year from a real CY## value or a CY## token in the file name. Downloads require that same campaign-year token when a year is selected, so undated DAO files do not fill the table. Daily Load and Totals filter on CAMPAIGN_YEAR.
